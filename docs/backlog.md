## B1. 审计持久化（当前：内存环形 100 条）

- **2026-11-15 决定：暂不做持久化。** 先把插件页/README/工具描述改成“同一次运行内可撤回 +
  收据恢复”，避免继续承诺“以后还能一键回滚”。等出现跨进程查账/回滚的真实需求、或配置写入
  频率明显上升时，再按下面的解法做。
- **现状**：`history` / `revert` 的审计记录只存在插件内存里；插件重载或进程结束后清空。
- **影响**：跨进程无法回滚之前写入的配置；审计不能当长期账本用。
- **适用场景判断**：日常“改完发现不对立刻回滚”不受影响；真正的缺口是“隔了一次重载/重开后，
  还想按 auditId 回滚”。如果配置坏到 DSH 起不来，只能先手工恢复 profile 文件，持久化审计也
  读不到——它不是启动故障的救援通道。
- **解法**（约 3–4h）：用官方 `storageDomain` + 自有 domain（`defineDomain` + zod schema），需给插件新增 peerDependencies：`@deepseek-ai/dsh-storage-domain`、`zod`（已确认 Desktop 安装区自带这两个包）；打不开 domain 时回落内存并如实告知。注意敏感值：存原值才能完整回滚，但会复制一份密钥；只存掩码则敏感字段不能自动回滚。
- **已完成的低成本缓解**：写入成功后，结果里输出可手工粘贴的恢复片段（写入前的覆盖值 +
  操作步骤）；跨进程按收据恢复。

## B2. 审批策略是插件级，不是按行

- **现状**：只有 `approval: ask`（每次写入都要批准）或 `never`（只读）两个总开关。
- **影响**：不能"无害的行免审批、危险的行强制审批"；每次改配置都要点一次同意。
- **解法**（约 1–2h）：配置加 `approvalRows`（行 id → `ask|auto`），默认 `ask`；工具按行解析策略；测试覆盖 auto/ask/never 三种组合。
- **优先级**：低（日常改配置频次低，点一次同意成本可接受）。

## B3 执行记录（2026-11-09 21:5x 真机）

- **做了什么**：对 `workbench` 行做了一次真实、可回滚的写入（`requirePreview: false`），然后 `reset` 复原。
- **结果**：
  - 预览 → 凭证 `d11c02158b43c260` → apply → **真实写入成功**，覆盖值变成 `{"requirePreview":false}`；
  - 审批链路真实走通：`approval.request` 被调用并返回 `allowed-once` 后完成写入；
  - 写入后立即 `history`：**空**（见下）；`reset` 预览 → 凭证 → apply → 覆盖值恢复 `{}`，最终 `get` 确认回到初始状态。
- **重要发现（B1 的现场证据）**：
  - 修改的是 `workbench` **自己这一行** → 写入触发该行 fiber 重建 → 插件实例被销毁重建 → **审计记录当场清空**；
  - 所以"改自己这行"时，`revert` 实际上不可能用（连刚写的那条记录都没了），只能用 `set/reset` 手工复原。
  - 对**其它行**的写入不会重建本插件实例，审计会保留；但由于没有持久化，插件重挂/重启仍会丢。
- **关于"人工点击同意"**：本部署的审批回答者是自动审查（auto-review，LLM）而不是人工弹窗，这次是自动批准（`allowed-once`）；所以"真人点同意"这个具体交互没有发生。若要验证人工弹窗，需要临时调整审批回答者配置（部署级，不建议为测试改）。

## B6. 只读 `presets` 动作：让公共插件自适应部署 roster（计划：下一版）

- **背景**：`dsh_session_manage.start` 的 `agentPreset` 描述硬编码了官方四个 preset 的一句话说明。
  DSH 0.2.2-rc.3 起部分事实已过时（`standard` 在桌面 profile 下也启用 `plugin_manager`、也有
  `customSkillDirs`；`cordis` 的独有项只剩 `cordis_inspect`），而且部署私有 preset 无法出现在
  公共插件的描述里。
- **决定**：公共插件不写任何部署私有的 preset 名，改为提供一个只读动作 `action=presets`
  返回当前部署的 roster：`id` / `name` / `description` / `order` / `broken?`（来源 `agentPresets`
  服务）；工具描述改成可移植的选型原则（省略 `agentPreset` = 部署默认；只有任务明确需要不同
  执行模型时才显式选；选前先查 `presets`）。
- **收益**：同一个公共包对所有部署成立；每个部署的私有 preset 靠自身的 `name`/`description`
  被 agent 发现，不再需要把本机名字写进公共文案。
- **注意**：动作只读、不需要审批；`description` 可能较长或含第三方文本，返回要截断并注明来源；
  roster 变化（装/卸 preset bundle）要在下一次调用反映，不能缓存到进程生命周期。
- **状态**：用户 2026-11-16 同意；计划随下一次发版（0.2.2 或 0.3.0）加入，当前补丁不做。
